# NKO Supabase Auth検証

NKOのGAS版を維持したまま、Supabase Authのメールアドレス＋パスワード認証だけを検証する。

## 構成

- Google OAuth・GCPは使用しない。
- 公開サインアップ、確認メール、招待メール、パスワード再設定メールは使用しない。
- ユーザーは管理者がSupabase Dashboardから作成し、メールを確認済みにする。
- 認証検証ページは`/<group-path>/auth-preview.html`とする。
- 検証ページはNKOのGAS APIや支払いデータへアクセスしない。
- アクセストークンとリフレッシュトークンは画面に表示しない。

## Supabase Dashboard設定

1. Authenticationの設定で公開サインアップを無効にする。
2. Emailプロバイダーは有効のままにする。
3. Authentication > Usersからテストユーザーを1人作成する。
4. 十分に長いランダムな初期パスワードを設定する。
5. メール送信を使わないため、ユーザーをメール確認済みとして作成する。

管理者APIを利用する場合、Secret keyまたはService Role keyは信頼できるサーバーだけで使用する。GitHub Pages、ブラウザ、Git、公開設定には置かない。

## 検証項目

1. テストユーザーでログインできる。
2. ページを再読み込みしてもログイン状態が継続する。
3. ブラウザを閉じて開き直してもログイン状態が継続する。
4. 未登録メールアドレスや誤ったパスワードではログインできない。
5. ログアウト後はセッションが利用できない。
6. 画面に表示されるユーザー情報が、メール、UUID、メール認証用メタデータの範囲である。
7. GoogleプロフィールやGoogle OAuthの情報が存在しない。

認証検証が完了するまで、既存の`/nko/`のアクセスキー認証は変更しない。
