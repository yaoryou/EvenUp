## 1. 基本方針

- スマートフォン縦持ちを主対象とする。
- 下部タブは「記録」「精算」「履歴」の3つとする。
- 精算画面内で「個別精算」と「まとめて最適化」を切り替える。
- 個別精算は任意の1組・任意の一部金額を記録できる。
- 最適化精算は全ルート一括記録だけを許可する。
- 元の支払いと残債内訳をいつでも確認できるようにする。
- 危険操作は確認ダイアログを挟む。

## 2. レイアウト

┌──────────────────────────┐
│ EvenUp             設定  │
├──────────────────────────┤

- 対応最小幅は320px。

- タップ領域は44×44px以上。
- 下部タブはセーフエリアを考慮する。
- URLは`#/record`、`#/settlement`、`#/history`とする。

## 4. 起動・認証

### `SCR-00` 起動

- 保存済みキーの検証と`bootstrap`取得中に表示する。
- 未認証時に業務データを一瞬表示しない。
- キーなし・不正なら`SCR-01`へ進む。

### `SCR-01` アクセスキー入力

```text
EvenUp

グループのアクセスキー
[                         ]

[はじめる]
```

- 入力は`password`形式。
- 認証中は入力とボタンを無効化する。
- 成功時はキーを`localStorage`へ保存する。
- 不正時は「アクセスキーが正しくありません」と表示する。

## 5. `SCR-10` 支払い記録

```text
支払いを記録

内容
[ラーメン                 ]

金額
[                  1,000円]

支払った人
[ナカチ ▼]

割り勘する人       全員選択
[✓ナカチ] [✓シャ卿]
[✓チンピラ]

[記録する]
```

### 入力

| 項目 | 初期値 |
| --- | --- |
| 内容 | 空 |
| 金額 | 空 |
| 支払者 | 設定画面の操作ユーザ、なければ直前値、なければ先頭 |
| 対象者 | 全有効メンバー |

- 金額は数字入力と3桁区切り表示を行う。
- 対象者は1人以上必須。
- 支払者が対象外でもよい。
- 登録成功後、内容・金額を空、対象者を全員へ戻す。
- 通信失敗時は入力と`request_id`を保持する。

## 6. `SCR-20` 精算

### 6.1 共通上部

```text
精算

[ 個別精算 ][ まとめて最適化 ]

現在の残債  3件 / 2,667円
```

- セグメント切替の初期値は`個別精算`。
- 選択値は端末内に保持してよい。
- 切替は表示だけを変え、サーバーの残債データを共用する。

### 6.2 個別精算

元の直接債務を2人ごとに相殺し、差額だけを実送金候補として表示する。

```text
個別精算

┌──────────────────────────┐
│ シャ卿 → ナカチ          │
│ 実送金          1,034円 │
│ 逆方向300円を相殺       │
│                          │
│ ラーメン          334円 │
│ レンタカー代    1,000円 │
│                          │
│ [この送金を記録]         │
└──────────────────────────┘

┌──────────────────────────┐
│ チンピラ → ナカチ        │
│ 残り            1,333円 │
│ [内訳を見る]             │
│ [この送金を記録]         │
└──────────────────────────┘
```

- カードごとに相殺後の送金元、送金先、実送金額、相殺額、元支払い内訳を表示する。
- 内訳は古い支払い順に表示する。
- 任意のカードだけ操作できる。
- 他カードの精算を要求しない。
- A→BとB→Aの残額が同額の場合は、送金なしの「相殺を記録」として表示する。
- 残債がない場合は「個別に精算する残額はありません」と表示する。

### 6.3 `SCR-21` 個別送金確認

```text
送金を記録

シャ卿 → ナカチ

残り 1,334円

送金額
[              1,334 ] 円

古い支払いから順に充当されます。
・ラーメン 334円
・レンタカー代 最大1,000円

[戻る] [送金を記録]
```

- 初期金額はカード残額全額。
- 1円以上、カード残額以下へ変更できる。
- 入力額に応じた予定充当を画面上で参考表示する。
- 実際の充当はサーバー計算を正とする。
- 送金済みであることを確認する文言を表示する。
- `DIRECT_ROUTE_CONFLICT`時は記録せず最新候補へ更新する。

### 6.4 まとめて最適化

```text
まとめて最適化

全員分をまとめた場合のおすすめです。
一部だけ実施することはできません。

┌──────────────────────────┐
│ シャ卿 → ナカチ    800円 │
└──────────────────────────┘
┌──────────────────────────┐
│ チンピラ → シャ卿  500円 │
└──────────────────────────┘

対象残債 4件 / 2,667円
送金      2件

[全ルートを一括で記録]
```

- 説明文で全ルート実施が前提であることを常時明示する。
- 各ルートに個別の完了ボタンを置かない。
- 送金元・先・金額を編集できない。
- 送金0件で相殺できる場合は「実際の送金なしで相殺できます」と表示する。

### 6.5 `SCR-22` 最適化精算確認

```text
まとめて精算しますか？

表示された全ルートを実際に送金した
ことを確認してください。

・シャ卿 → ナカチ 800円
・チンピラ → シャ卿 500円

この操作で対象の残債をすべて
精算済みにします。

[戻る] [一括で記録]
```

- 全ルートを再掲する。
- 一部だけ実施した場合は戻って個別精算を使うよう案内する。
- `SNAPSHOT_CONFLICT`時は自動記録せず最新ルートを表示する。

### 6.6 メンバー別収支

両方式の下部に折りたたみ表示する。

| 残高 | 表示 |
| --- | --- |
| 正 | 受け取る |
| 負 | 支払う |
| 0 | 精算なし |

### 6.7 未精算支払い

- `UNSETTLED`と`PARTIALLY_SETTLED`を新しい順に表示する。
- 一部精算には`残り○円`を表示する。
- タップで`SCR-23`を開く。

```text
未精算の支払い

[一部精算]
レンタカー代       9,000円
残り               2,000円 >
```

## 7. 支払い編集・取消

### `SCR-23` 支払い編集

- 支払い日時、内容、金額、支払者、対象者、負担額、残債を表示する。
- 有効充当が0円の場合だけ編集と取消を提供する。
- 有効充当がある場合は読み取り専用とし、次を表示する。

```text
この支払いは一部または全部が精算済みです。
編集するには、関連する送金を新しい順に
取り消してください。
```

### `SCR-24` 支払い取消確認

- 元の支払いが履歴へ取消済みとして残ることを明示する。
- 有効充当がある場合は開けない。

## 8. 最新送金取消

精算画面下部に最新の有効な送金バッチを表示する。

```text
直前の精算

個別精算  6/25 20:00
シャ卿 → ナカチ 1,000円

[この精算記録を取り消す]
```

### `SCR-25` 最新送金取消確認

```text
直前の精算記録を取り消しますか？

シャ卿 → ナカチ 1,000円

元の支払いに充当された金額が戻り、
残債が再計算されます。
実際の送金を自動で返金する機能ではありません。

[戻る] [記録を取り消す]
```

- 最適化バッチの場合は全ルートを再掲する。
- 最新でなくなっていた場合は取消せず最新状態へ更新する。

## 9. `SCR-30` 履歴

```text
履歴

[ すべて ][ 支払い ][ 送金 ]

6/25 20:00 [個別精算]
シャ卿 → ナカチ     1,000円 >

6/25 12:34 [一部精算]
レンタカー代         9,000円
残り                 2,000円 >

[さらに読み込む]
```

### 9.1 取得

- 初回表示時に20件取得する。
- 追加も20件とする。
- 表示種別を変えた場合はその種別の先頭から取得する。
- 更新操作後は履歴キャッシュを無効化する。

### 9.2 バッジ

支払い:

- 未精算
- 一部精算
- 精算済み
- 取消済み

送金:

- 個別精算
- 最適化精算
- 取消済み

### `SCR-31` 支払い詳細

- 元の支払い情報
- 対象者別の負担額
- 対象者別の充当済み額と残額
- 全体状態
- 関連する有効・取消済み送金バッチ

「前回未精算」という新規支払いは表示しない。残額を元支払いの内訳として表示する。

### `SCR-32` 送金詳細

- モード
- 実施日時
- 送金ルート
- 充当した元支払い、債務者、金額
- 有効・取消済み状態

最適化精算では、送金ルートと充当内訳が1対1対応しないことを説明する。

## 10. `SCR-40` 設定

- この端末の操作ユーザを選択・保存する
- 最新状態を読み込む
- この端末からログアウト
- アプリバージョン

操作ユーザは支払い記録画面の支払者初期値として使用する。支払いごとに支払者は変更できるが、登録によって操作ユーザ設定は変更しない。

ログアウト時はアクセスキー、操作ユーザ、直前支払者、画面状態、メモリ上の業務データを削除する。

## 11. ローディング・エラー

| 場面 | 表示 |
| --- | --- |
| 初期化 | 全画面ローディング |
| ボタン処理 | ボタン内スピナー |
| 履歴初回 | スケルトン |
| 競合 | 最新データへ更新するバナー |
| 残債なし | 「現在、未精算の残額はありません」 |
| データ不整合 | 全画面エラー、管理者連絡案内 |

- 通信失敗時に入力内容を失わない。
- 競合時に自動で送金を記録し直さない。
- 成功は下部タブ上のトーストで通知する。

## 12. アクセシビリティ

- 本文は16px以上を基本とする。
- 入力とラベルを関連付ける。
- 色だけで状態を示さない。
- ダイアログでフォーカストラップを行う。
- 通知は`aria-live`へ出す。
- キーボードだけで操作できる。
- `prefers-reduced-motion`へ対応する。

## 13. 画面遷移

```text
起動 → 認証 → 記録
              ├─ 精算
              │   ├─ 個別精算 → 個別送金確認
              │   ├─ 最適化 → 一括確認
              │   ├─ 支払い編集 → 支払い取消確認
              │   └─ 最新送金取消確認
              ├─ 履歴
              │   ├─ 支払い詳細
              │   └─ 送金詳細
              └─ 設定 → ログアウト
```

## 14. 画面受入条件

1. 320px幅で横スクロールが発生しない。
2. 個別精算で1組だけを選んで送金記録できる。
3. 個別精算で提案額未満を入力できる。
4. 個別送金確認でFIFO充当予定を確認できる。
5. 最適化画面に個別完了ボタンが存在しない。
6. 最適化確認で全ルートが再掲される。
7. 一部精算支払いに元の内容と残額が表示される。
8. 履歴から支払いと送金の両方を追跡できる。
9. 最新送金取消が実際の返金ではないと明示される。
10. 未認証時に業務データを表示しない。
